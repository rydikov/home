# Умный дом строится на базе Wirenboard, а здесь описаны правила для него

Правила написаны на Type Script, компилируются в Java Script ES5 и загружаются на контроллер для исполнения.

### У правил есть конвенция и структура:

Устройства описаны в виде классов, а в файле `src/wb-rules-modules/global-devices.ts` задается соответствие с расположением устройства в доме.
Например: 

```js
Cabinet_01: new RelayLight('wb-mr6cv3_217/K6') 
```
означает что в комнате `Cabinet` группе освещения `01` соответствуют `реле с выходом 6`.
Все группы освещения описаны в плане освещения, который находится в docs.

Основное удобство в том, что для того чтобы включить лампочку вместо:

```js
dev['wb-mr6cv3_217/K6'] = true;
```

Нужно указывать:

```js
RelayLights.Cabinet_01.on()
```

А для того чтобы подписаться на изменение топика вместо:

```js
whenChanged: ['mtdx62-mb_7/presence_status']
```

Нужно указать:

```js
whenChanged: [PresenceSensors.hall.presence_status_topic]
```

Также в классы выносится дополнительная логика и проверки.

### Правила именуются с префиксами:

`alarms.ts` оповещение об аномальном поведении устройств, например, устройство стало offline и т.д. Актуально для сторонних zigbee устройств.

`check-*.ts` проверка доступности устройств опрашивая их статус или время передачи данных. Актуально для сторонних устройств.

`run-*.ts` правила если что-то происходит от других контролов, нажали в выключатель, повысилась температура и т.д.

`sync-*.ts` синхронизация внешних устройств с виртуальными. Актуально для сторонних устройств.

### Сборка и деплой

Правила из `src/wb-rules/` и используемые ими модули из `src/wb-rules-modules/`
локально компилируются в JavaScript ES5 для `wb-rules`. На контроллер отправляется
содержимое `dist/es5/wb-rules/` и `dist/es5/wb-rules-modules/`.
В исходниках используются статические импорты, например
`import { WbDali } from '#wbm/global-devices'`: Rollup собирает зависимости
и преобразует импорты в вызовы `require()` для контроллера.

Все команды выполняются из `wirenboard/rules/` с Node.js 24.12.0 или совместимой версией.
Для локальной сборки:

```
pnpm build
```

Тесты работают с исходниками и не требуют предварительной сборки:

```
pnpm test
```

После сборки можно проверить план синхронизации без изменения файлов контроллера:

```
pnpm exec mirta deploy --profile default --dry-run
```

Для сборки и деплоя на контроллер через профиль `default`:

```
pnpm wb:deploy
```

Профиль включает очистку целевых каталогов (`cleanup: true`), в том числе удаление
старых `.ts` при переходе на `.js`. Файл `alarms.conf` защищён от удаления.
Скомпилированные файлы в `dist/es5/` вручную не редактируются.

После повышения версии фреймворка mirta нужно сделать:
```
pnpm install
```
